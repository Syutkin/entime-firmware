# ENTime - Настройки модуля

Все настройки модуля ENTime сохраняются в NVS (Non-Volatile Storage) через ESP32 Preferences API. Настройки можно сохранять и загружать через команды `save_config` и `load_config` (см. [PROTOCOL.md](PROTOCOL.md)).

---

## 📋 Обзор

Система настроек позволяет сохранять параметры конфигурации между перезагрузками устройства. Все настройки хранятся в разделе NVS с именем `"entime"`.

### Структура данных

Настройки организованы в иерархическую структуру JSON, сгруппированные по функциональным категориям:

```json
{
  "data": {
    "device": {
      "name": "...",
      "number": ...,
      "type": ...,
      "timezone_offset_min": ...
    },
    "sync": {
      "auto": ...,
      "source": ...,
      "ntp1": "...",
      "ntp2": "...",
      "ntp3": "..."
    },
    "wifi": {
      "active": ...,
      "ssid": "...",
      "passwd": "..."
    },
    "gps": {
      "enabled": ...
    },
    "touch": {
      "enabled": ...,
      "cal_valid": ...,
      "calibration": [0, 0, 0, 0, 0]
    }
  }
}
```

**Важно:**
- Настройки сохраняются только после явного вызова команды `save_config`
- При первом запуске используются значения по умолчанию
- Команда `factory_reset` сбрасывает все настройки к значениям по умолчанию
- Команда `touch_calibrate` выполняет калибровку и сохраняет `touch.calibration`/`touch.cal_valid`
- При частичном обновлении можно указывать только нужные группы или параметры внутри групп
- Явный `null` для известных настроек, групп и элементов калибровки недопустим: `save_config` возвращает ошибку `103` без применения изменений

## ⚙️ Список настроек

### Основные настройки устройства

#### `device.name`
- **Путь в JSON:** `data.device.name`
- **Тип:** `string`
- **По умолчанию:** `"ENTime"`
- **Описание:** Имя устройства для BLE и идентификации. Используется в качестве BLE device name.
- **Ограничения:**
  - Максимальная длина: 16 символов
  - Только ASCII символы (a-z, A-Z, 0-9, `-`, `_`)
  - Не может быть пустой строкой
- **Пример:** `"ENTime-1"`, `"MyENTime"`

#### `device.number`
- **Путь в JSON:** `data.device.number`
- **Тип:** `integer` (unsigned)
- **По умолчанию:** `1`
- **Описание:** Номер устройства для идентификации при соединении через BLE. Используется при запуске BLE для различения устройств в сети.
- **Ограничения:**
  - Диапазон: `1` до `255`
  - Только целые положительные числа
- **Примеры:**
  - `1` — первое устройство (по умолчанию)
  - `2` — второе устройство
  - `10` — десятое устройство

#### `device.type`
- **Путь в JSON:** `data.device.type`
- **Тип:** `integer`
- **По умолчанию:** `1`
- **Описание:** Тип устройства для определения роли в системе синхронизации времени. Устройство может быть либо стартовым (1), либо финишным (2).
- **Допустимые значения:**
  - `1` — стартовое устройство (по умолчанию)
  - `2` — финишное устройство
- **Ограничения:** Только одно из двух допустимых значений (1 или 2)
- **Примеры:**
  - `1` — устройство для старта измерения времени
  - `2` — устройство для финиша измерения времени

#### `device.timezone_offset_min`
- **Путь в JSON:** `data.device.timezone_offset_min`
- **Тип:** `integer` (signed)
- **По умолчанию:** `180`
- **Описание:** Смещение часового пояса относительно UTC в минутах. Положительное значение — восточнее UTC, отрицательное — западнее UTC.
- **Ограничения:** Диапазон `-720..840` минут.
- **Примеры:**
  - `0` — UTC
  - `180` — UTC+3 (Москва)
  - `330` — UTC+5:30
  - `345` — UTC+5:45
  - `570` — UTC+9:30
  - `-300` — UTC-5
- **Применение:** Применяется сразу, без перезагрузки

### Настройки синхронизации времени

#### `sync.auto`
- **Путь в JSON:** `data.sync.auto`
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Описание:** Включить автоматическую синхронизацию времени по GPS PPS и RTC. При `false` устройство не будет автоматически корректировать системное время, но будет отслеживать источники времени.
- **Ограничения:** Только `true` или `false`
- **Примечание:** Рекомендуется оставлять `true` для обеспечения точности времени
- **Применение:** Применяется сразу, без перезагрузки

#### `sync.source`
- **Путь в JSON:** `data.sync.source`
- **Тип:** `integer`
- **По умолчанию:** `0`
- **Описание:** Предпочтительный источник синхронизации времени. В режиме `0` (auto) устройство автоматически переключается между GPS и RTC в зависимости от доступности сигнала.
- **Допустимые значения:**
  - `0` — автоматический выбор источника (GPS при наличии PPS, иначе RTC)
  - `1` — принудительное использование GPS (fallback на RTC при потере сигнала)
  - `2` — принудительное использование RTC (GPS отключён)
- **Ограничения:** Только одно из трёх допустимых значений (0, 1 или 2)
- **Примечание:** При установке `1` (GPS) без сигнала GPS устройство всё равно переключится на RTC для обеспечения работы
- **Применение:** Применяется сразу, без перезагрузки

#### `sync.ntp1`
- **Путь в JSON:** `data.sync.ntp1`
- **Тип:** `string`
- **По умолчанию:** `"ru.pool.ntp.org"`
- **Описание:** Основной NTP сервер для команды `sync_ntp`.
- **Ограничения:**
  - Длина: 1..64 символа
  - Только ASCII символы (a-z, A-Z, 0-9, `-`, `.`)
- **Пример:** `"ru.pool.ntp.org"`
- **Применение:** Применяется сразу, без перезагрузки

#### `sync.ntp2`
- **Путь в JSON:** `data.sync.ntp2`
- **Тип:** `string`
- **По умолчанию:** `"time.google.com"`
- **Описание:** Резервный NTP сервер.
- **Ограничения:**
  - Может быть пустой строкой
  - Длина: 1..64 символа
  - Только ASCII символы (a-z, A-Z, 0-9, `-`, `.`)
- **Пример:** `"time.google.com"`
- **Применение:** Применяется сразу, без перезагрузки

#### `sync.ntp3`
- **Путь в JSON:** `data.sync.ntp3`
- **Тип:** `string`
- **По умолчанию:** `"time.cloudflare.com"`
- **Описание:** Третичный NTP сервер.
- **Ограничения:**
  - Может быть пустой строкой
  - Длина: 1..64 символа
  - Только ASCII символы (a-z, A-Z, 0-9, `-`, `.`)
- **Пример:** `"time.cloudflare.com"`
- **Применение:** Применяется сразу, без перезагрузки

### Настройки WiFi

#### `wifi.active`
- **Путь в JSON:** `data.wifi.active`
- **Тип:** `boolean`
- **По умолчанию:** `false`
- **Описание:** Включить или отключить WiFi модуль. При `true` устройство будет пытаться подключиться к WiFi сети с указанными SSID и паролем.
- **Ограничения:** Только `true` или `false`
- **Примечание:** WiFi можно включить для удаленного доступа и обновления прошивки

#### `wifi.ssid`
- **Путь в JSON:** `data.wifi.ssid`
- **Тип:** `string`
- **По умолчанию:** `""`
- **Описание:** Имя WiFi сети (Service Set Identifier) для подключения.
- **Ограничения:**
  - Максимальная длина: 32 символа
  - Может быть пустой строкой (если WiFi не используется)
- **Пример:** `"MyWiFi"`, `"HomeNetwork"`

#### `wifi.passwd`
- **Путь в JSON:** `data.wifi.passwd`
- **Тип:** `string`
- **По умолчанию:** `""`
- **Описание:** Пароль WiFi сети для подключения.
- **Обновление:** Отсутствующее поле сохраняет пароль, строка заменяет его, `""` очищает; `null` недопустим. В ответе `load_config` поле `passwd` отсутствует.
- **Ограничения:**
  - Максимальная длина: 64 символа
  - Может быть пустой строкой (для открытых сетей)
- **Пример:** `"mypassword123"`, `""` (для открытой сети)
- **Примечание:** Пароль хранится в открытом виде в NVS. Для безопасности рекомендуется использовать защищённые сети.

---

### Настройки GPS

#### `gps.enabled`
- **Путь в JSON:** `data.gps.enabled`
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Описание:** Включать GPS при загрузке. При `false` пин питания GPS `GPS_POWER_PIN` выставляется в `LOW`, а GPS UART/NMEA не инициализируется.
- **Ограничения:** Только `true` или `false`
- **Применение:** Требуется перезагрузка

---

### Настройки Touch

#### `touch.enabled`
- **Путь в JSON:** `data.touch.enabled`
- **Тип:** `boolean`
- **По умолчанию:** `true`
- **Описание:** Включает или отключает обработку touch-событий в HAL.
- **Ограничения:** Только `true` или `false`
- **Применение:** Применяется сразу, без перезагрузки

#### `touch.cal_valid`
- **Путь в JSON:** `data.touch.cal_valid`
- **Тип:** `boolean`
- **По умолчанию:** `false`
- **Описание:** Признак валидной калибровки touch. Пока `false`, пользовательский ввод touch блокируется и при старте автоматически запускается мастер калибровки.
- **Ограничения:** Только `true` или `false`

#### `touch.calibration`
- **Путь в JSON:** `data.touch.calibration`
- **Тип:** `array[5]` (`uint16`)
- **По умолчанию:** `[0, 0, 0, 0, 0]`
- **Описание:** Массив коэффициентов калибровки, совместимый с `TFT_eSPI::setTouch`.
- **Ограничения:**
  - Ровно 5 элементов
  - Каждый элемент — целое беззнаковое 16-битное число (`0..65535`)
- **Примечание:** Для обратной совместимости также поддерживается передача отдельных полей `touch.cal0..touch.cal4`.

## 💾 Примеры использования

### Сохранение настроек

**Запрос:**
```json
{
  "cmd": "save_config",
  "data": {
    "device": {
      "name": "ENTime-Lab",
      "number": 1,
      "type": 1,
      "timezone_offset_min": 180
    },
    "sync": {
      "auto": true,
      "source": 0,
      "ntp1": "ru.pool.ntp.org",
      "ntp2": "time.google.com",
      "ntp3": "time.cloudflare.com"
    },
    "wifi": {
      "active": false,
      "ssid": "",
      "passwd": ""
    },
    "gps": {
      "enabled": true
    },
    "touch": {
      "enabled": true,
      "cal_valid": false,
      "calibration": [0, 0, 0, 0, 0]
    }
  }
}
```

**Ответ:**
```json
{
  "cmd": "save_config",
  "saved_keys": 5,
  "storage_usage_percent": 15,
  "status": "ok"
}
```

### Загрузка настроек

**Запрос:**
```json
{"cmd": "load_config"}
```

**Ответ:**
```json
{
  "cmd": "load_config",
  "data": {
    "device": {
      "name": "ENTime-Lab",
      "number": 1,
      "type": 1,
      "timezone_offset_min": 180
    },
    "sync": {
      "auto": true,
      "source": 0,
      "ntp1": "ru.pool.ntp.org",
      "ntp2": "time.google.com",
      "ntp3": "time.cloudflare.com"
    },
    "wifi": {
      "active": false,
      "ssid": ""
    },
    "gps": {
      "enabled": true
    },
    "touch": {
      "enabled": true,
      "cal_valid": false,
      "calibration": [0, 0, 0, 0, 0]
    }
  },
  "status": "ok"
}
```

### Частичное обновление

При сохранении можно указать только те параметры или группы, которые нужно изменить. Остальные останутся без изменений:

**Пример 1: Обновление одного параметра в группе**
```json
{
  "cmd": "save_config",
  "data": {
    "device": {
      "timezone_offset_min": 330
    }
  }
}
```

**Пример 2: Обновление всей группы**
```json
{
  "cmd": "save_config",
  "data": {
    "sync": {
      "auto": false,
      "source": 1
    }
  }
}
```

**Пример 3: Обновление touch-калибровки**
```json
{
  "cmd": "save_config",
  "data": {
    "touch": {
      "enabled": true,
      "cal_valid": true,
      "calibration": [3800, 220, 3700, 240, 7]
    }
  }
}
```

## 📝 Примечания по реализации

1. **Хранение:** Все настройки хранятся в NVS namespace `"entime"` с использованием Preferences API
2. **Валидация:** При сохранении проверяется корректность типов и диапазонов значений
3. **Обратная совместимость:** При отсутствии настройки в NVS используется значение по умолчанию
4. **Размер:** NVS namespace ограничен 4000 байт. Текущие настройки занимают:
   - Минимум (заводские значения): ~260 байт
   - Максимум (при заполнении всех строковых полей): ~420 байт
